# 使用与维护

本文件维护安装、恢复、支持边界和官方插件接入点。README 是项目入口。

## 命令

在仓库根目录运行，Windows 默认查找当前用户 `.vscode/extensions`；Linux 同时检查 `.vscode-server/extensions` 和 `.vscode/extensions`，支持 `linux-arm64`、`linux-x64` 包。自动查找按当前运行平台、安装清单和过期标记选择插件；仅一处安装时自动选择，多个宿主目录均有候选时，在交互终端列出每处的当前最高版本、用途和完整路径，输入编号选择本次操作的目标。SSH Remote 窗口选择“VS Code Server（Remote SSH）”，直接打开该机桌面 VS Code 时选择“本机桌面 VS Code”；无效编号会提示重选，`q`、回车或输入结束会取消。菜单写入标准错误，不混入标准输出的 JSON。非交互环境不自动选择，须用 `--extension "插件绝对路径"` 指定目录；自定义 VS Code Server 安装位置也使用此参数。选择仅对本次命令生效，不保存默认目标。

```powershell
node tools/layer.mjs status
node tools/layer.mjs probe
node tools/layer.mjs plan --compatible
node tools/layer.mjs apply --compatible --confirm
node tools/layer.mjs restore --confirm
```

`status`、`probe` 和 `plan` 不修改文件。未指定目录时，命令读取 VS Code 的 `.obsolete` 清单并选择当前未过期的最高版本，不把残留的旧插件目录误报为当前版本。缺失或空白的 `.obsolete` 视为没有过期标记，仍遵循安装清单；非空但损坏的 `.obsolete` 或损坏的 `extensions.json` 会停止发现并指出文件路径，脚本不改写这些清单。`probe` 的 `compatible` 与 `patchCompatible` 仅表示补丁结构兼容，`runtimeSupport.verified` 为 `false`；真正的运行环境支持在 VS Code 内初始化时判断。`probe`、`plan` 和正式安装共用生成代码语法检查，按宿主 CommonJS、前端 ES Module 和 bootstrap 普通脚本分别只解析、不执行；更新时检查失败会保留旧补丁和备份。`probe` 动态识别页面入口及路由、目录和首页模块，并实际生成内存补丁；只有所有结构化接入点唯一且完整时才报告兼容。`--compatible` 忽略固定版本和整文件哈希，但不跳过官方扩展身份、接入点唯一性、输出语法、备份与冲突检查。`apply` 和 `restore` 会修改官方插件安装目录，必须显式加 `--confirm`。关闭所有 VS Code 窗口后应用或恢复，再手动启动 VS Code；打开的 Webview 不会自动热更新。项目脚本不会启动 VS Code 或安装软件。

补丁修改七个官方文件：宿主入口 `out/extension.js`、页面入口 `webview/index.html`、当前版本的前端路由模块、首页标题／最近聊天模块、聊天创建／输入模块、活动分类模块和推理摘要渲染模块。新增一个宿主适配文件和 `webview/vscodex-layer` 下的前端资源，不修改官方历史聊天数据、账户或系统配置。

原件和校验清单保存在插件目录的 `.vscodex-layer`，同一补丁重复应用不会重复注入。恢复核对当前文件和备份后回写原件、删除新增资源和备份；空的增强资源目录可能保留。恢复不清除聊天历史和导航偏好。

## 兼容与恢复

严格模式针对插件版本 `26.5930.51102` 的已核查 Windows 包，校验五个原有接入文件的 SHA-256；两个推理摘要模块额外进行结构检查并记录原件哈希。兼容模式按稳定属性发现当前资源，动态捕获压缩局部变量，并要求每个转换点唯一。当前包含推理摘要的完整补丁已在 Linux ARM64 包 `26.51007.21434` 上通过无界面验证；Windows 包 `26.5930.51102`、`26.51002.51308` 的原有导航接入已验证，新增摘要接入需在目标包上重新执行检查。任何目标包必须先通过 `probe`，结构不完整或存在多个候选时拒绝修改。

首次安装或刷新到当前仓库代码，都只需在关闭所有 VS Code 窗口后运行 `node tools/layer.mjs apply --compatible --confirm`（已核查 Windows 包也可省略 `--compatible`）。已有补丁与当前代码不同时，脚本先校验全部旧文件、原件备份和新补丁，再在同一操作锁内自动恢复并应用当前补丁；相同补丁重复执行不会修改文件。`restore --confirm` 用于单独卸载补丁，更新时无需手动执行。恢复文件补丁不会删除官方草稿。

官方更新、其他工具改写文件或备份损坏时，脚本拒绝覆盖。检查 `status` 输出后处理对应版本；不要用旧备份覆盖新插件。备份先在 `.vscodex-layer.prepare-*` 准备，完整校验清单就绪后才启用正式备份并写入补丁。若补丁写入中断，保留完整备份并运行恢复命令。`status` 会区分准备残留、空备份目录和非空但清单缺失；空目录可安全清理，非空无清单目录不会被恢复命令删除。重新应用只有在全部目标通过原件校验后，才将其保留为 `.vscodex-layer.orphan-*` 并继续。准备及隔离残留保留供人工检查，不用于自动恢复。进程意外退出可能留下 `.vscodex-layer.lock`，确认没有补丁进程后才能手动移除该锁文件。

## Remote SSH 使用

支持 Windows VS Code 客户端通过 Remote SSH 连接 Rock 5B 等 Linux 主机。增强层必须随 Codex 扩展运行在远程工作区宿主；宿主检查要求当前扩展为 Workspace 类型、运行平台为 Linux、插件为该宿主的文件资源。VS Code 将客户端的 SSH 工作区 URI 转成远程宿主上的 `file:` URI 后传给扩展，因此工作区按当前宿主的绝对文件目录校验；客户端文件对应的 `vscode-local:` URI 与虚拟目录均拒绝。WSL、容器、虚拟工作区及运行在 Windows 客户端的 Codex 扩展暂不支持。可用 VS Code 的“Developer: Show Running Extensions”确认运行位置。

在 5B 上的仓库目录运行只读命令：

```sh
node tools/layer.mjs status
node tools/layer.mjs probe
node tools/layer.mjs plan --compatible
```

需要显式指定时，使用 `--extension "/home/ubuntu/.vscode-server/extensions/openai.chatgpt-26.51007.21434-linux-arm64"`；版本目录随官方更新改变。应用及恢复均在远程主机上进行，先关闭连接该主机的 VS Code 窗口，保留独立 SSH 终端，再运行 `apply --compatible --confirm` 或 `restore --confirm`，之后重新连接。

聊天列表来自当前远程宿主的现有 App Server 连接，不汇总 Windows 或其他 SSH 主机的历史。官方扩展在宿主启动 Codex 进程，并用 `hostId: "local"` 转发该连接的消息；这里的 local 表示扩展宿主上的连接，SSH 下是远程 Linux 主机。项目目录校验使用该宿主的 Node 文件系统，新聊天沿用官方草稿、创建及发送流程。

Linux ARM64 包 `26.51007.21434` 的结构探测、生成宿主入口、模拟 SSH 初始化和临时副本补丁检查已通过；真实 Windows → Rock 5B 窗口中的首次发送、流式回复、停止及审批仍需人工验收。

## 接入边界

### 推理摘要

增强层启用时，聊天活动列表保留后端实际返回的非空推理摘要。生成中、完成后和历史摘要都默认折叠；点击“思考”行的展开控件查看完整正文，生成中展开后实时更新。手动展开／收起的选择在该摘要组件存续期间保留，任务完成不强制改变状态。正文取消固定小窗口，用聊天页面统一纵向滚动；正文、长路径和代码自动折行并保留换行。空摘要不生成额外行。

“思考”行旁的打开详情图标使用 VS Code 内置 Markdown 预览，在主编辑区显示当前摘要，生成中同步更新。每个 Codex 面板复用一份只读内存文档，仅点击后转发所选摘要，其他聊天／宿主／摘要不会覆盖它；不写磁盘、不保存到导航偏好，也不请求模型。阅读实时更新依赖原聊天的摘要组件保持挂载；切换到其他聊天、关闭面板或停用增强层后不继续追踪原摘要。主编辑区阅读需要 VS Code 内置 Markdown 预览功能可用。重新加载页面后折叠状态重置。

摘要来自官方 `reasoning.summary` 转换后的可读文本，使用官方 Markdown 和折叠组件渲染，不读取加密推理或补出未返回的内容。`model_reasoning_summary = "none"`、模型／提供商不返回摘要、历史没有保存摘要时，无内容可展开；本补丁不修改 `config.toml` 或重新请求旧回复。返回原版界面同步隐藏摘要，重新启用增强层后恢复显示；完全卸载使用 `restore --confirm`。

接入点位于动态识别的 `agent-activity-item-*.js` 和 `sites-end-resource-*.js`。活动分类保留摘要独立项，组件桥接使用 React 外部状态订阅，避免切换增强层后旧聊天继续显示摘要。原生事件处理、线程数据和摘要保存仍由官方负责。

### 归档聊天

导航展开时，底部的归档箱图标打开“已归档聊天”；顶部返回箭头回到普通项目聊天。切换只改变左侧列表，右侧当前聊天及草稿保持原样。归档视图首次默认显示全部项目，可切换“仅当前项目”，按项目名、完整路径或聊天标题搜索。两个视图分别保留本次面板内的搜索、筛选、折叠、滚动和列表焦点，重新启用导航默认进入普通列表。

归档列表读取当前扩展宿主的完整分页，Remote SSH 下为远程宿主记录；只显示有归档聊天的项目，不显示空工作区、空手动项目、新建、置顶、项目操作菜单及运行／未读状态。项目内按最后更新时间从新到旧排列，时间标签不是归档时间。

每条记录右侧的恢复图标只取消归档，成功后从归档列表移除、更新普通列表，并提供“查看已恢复的聊天”入口；失败保留条目并允许重试。标题下明确显示“恢复后查看”，点击标题会先恢复再打开原生聊天。当前接入未提供保持归档状态的正文预览。恢复使用官方聊天服务，保留工作区准备、聊天缓存加载和原生通知；恢复后若原生加载失败，提示“已取消归档但加载失败”，不会自动切换右侧。恢复处理中禁用对应行，防止重复提交。

列表首次进入时加载；读取失败保留已有内容，可刷新重试。普通与归档列表独立缓存，过期分页响应不会覆盖另一视图或重新加入已恢复条目。原生恢复资源缺失、结构变化或接入点不唯一时，适配检查拒绝生成补丁。本功能需要按安装命令更新插件补丁后生效，真实 VS Code 恢复及工作区恢复仍需人工验收。

### 项目聊天导航

项目按聊天工作目录分组，完整路径区分同名目录。“全部项目”右侧的文件夹＋用于添加已有目录，支持输入当前宿主的绝对路径或使用 VS Code 文件夹选择器。普通目录、仓库子目录和 worktree 均可添加，不要求包含 Git 仓库或 `AGENTS.md`。Remote SSH 下选择远程宿主目录。当前工作区没有聊天时仍显示空项目；无法确定目录的聊天放在“未分类”。多根工作区的各根目录均标记为当前项目。“仅当前项目”按规范化后的完整路径精确匹配，不合并子目录或 worktree，也不承诺同步桌面端手动调整的项目归属及所有桌面空项目。聊天列表读取完整分页，不限制为最近 50 条。

“仅添加”保存目录并显示空项目，保持右侧聊天；“添加并新建聊天”保存后打开该目录的官方草稿，首次发送才创建聊天。添加成功切换为全部项目、清除搜索并展开定位项目；重复路径定位已有分组，同名不同路径分别显示。目录选择等待用户选择，不受普通请求的 30 秒超时限制；取消选择保留输入，校验或保存失败保留表单；已保存但草稿打开失败时保留项目并提示点击项目 `＋` 重试。项目操作提示独立于聊天列表读取状态，自动刷新不会覆盖提示。表单 Enter 执行添加并新建聊天，Esc 取消并恢复入口焦点。

项目行支持右键或 `Shift+F10` 打开项目菜单，提供复制文件夹路径；手动添加的项目还提供“移除添加记录”，只取消目录登记，保留文件夹、草稿及聊天。没有其他来源的空项目移除后消失；有历史聊天、属于当前工作区或保持置顶的项目仍显示。取消置顶不影响手动登记；文件夹失效后仍可移除记录。

点击项目折叠或展开；搜索项目名、路径或聊天标题。搜索期间展开匹配内容。项目内聊天按创建时间从新到旧排列，新聊天出现在所属项目顶部；发送消息、任务状态变化、改名和刷新不按最近活动重新排列。相同创建时间按聊天编号排序，缺少有效创建时间的聊天放在末尾并按编号排序。搜索保留匹配聊天的相对顺序。历史列表首次加载完成全部分页后统一显示；加载期间新聊天仍通过创建事件立即入列，刷新保留已有列表、滚动位置和焦点。活动状态直接更新圆点，不触发完整分页；列表增删、改名及目录变化合并安排刷新，读取中的有效结果先显示，再执行一次必要的后续读取。已归档或恢复条目按最新归属过滤，避免迟到结果重新加入旧视图。点击聊天只切换右侧官方页面，不改变 VS Code 工作区或聊天原有工作目录。当前聊天由官方路由同步高亮。

项目行 `＋` 左侧的图钉用于置顶／取消置顶：未置顶时悬浮或键盘聚焦项目行才显示，置顶后常驻。置顶项目按置顶先后排在顶部，新置顶项目加入末尾；其余项目保持当前项目优先，按项目名及完整路径固定排序；未分类放在末尾，不随聊天活动移动。筛选和搜索仍只显示符合条件的项目，匹配的置顶项目优先。置顶以完整路径区分同名目录和 worktree，点击不切换聊天、不折叠项目、不清除蓝点。没有聊天的置顶目录仍保留“暂无聊天”和新建入口；未分类不提供置顶。路径、名称和顺序保存在当前扩展宿主的导航偏好中，重开面板后恢复，不跨宿主同步。

聊天行右侧的 `⋯` 在悬浮、键盘聚焦或菜单打开时显示，右键聊天行也可打开。菜单挂载官方聊天操作组件，提供重命名、分享、复制深度链接／Markdown／工作目录及归档，实际可用性沿用官方判断。打开菜单不切换右侧聊天、不清除蓝点；菜单绑定点击的聊天编号，刷新列表不更换操作对象。Enter／空格打开，菜单内的方向键、Enter 和 Esc 沿用官方处理；菜单和子菜单使用官方浮层布局，列表滚动或窗口尺寸变化时关闭菜单。原生对话框打开期间先完成或关闭它，再操作其他聊天。

重命名成功后列表按新标题刷新。归档沿用官方运行中和关联任务的确认流程，失败保留聊天；成功后移除对应条目，归档非当前聊天不切换右侧，归档当前聊天返回最近使用的新聊天草稿入口并保留草稿。复制和分享使用官方内容及流程，不通过模型生成。左侧菜单不注册另一套全局聊天快捷键。加载失败在导航区提示，原版聊天页面保持可用。菜单接入点按结构探测，缺失或歧义时拒绝生成补丁。

聊天行右侧用绿色圆点表示运行中，蓝色圆点表示等待审批、等待输入、运行出错或本轮已结束尚未查看；悬浮可查看具体状态。当前正在打开的对话结束时也保留蓝点。在可见且有焦点的聊天正文中使用滚轮、触控板、滚动条或键盘滚动，本轮已完成回复的实质正文进入可视区并保持约 300 毫秒后，自动清除结束提示，不要求长回复滚到末尾。阅读旧消息、操作左侧导航、单纯自动滚动或隐藏／失去焦点的面板不视为已读；回复编号或正文接入点无法确认时保留蓝点。点击聊天行或重新切入该聊天也可清除结束提示；尚未处理的审批、输入和错误状态继续显示。开始新一轮时清除上一轮的结束提示，旧阅读回调不能清除新轮次提醒。项目折叠时，项目行汇总显示蓝点，展开即可定位聊天。结束提示随导航偏好保存，历史空闲聊天不会一律标为未读；未打开 Codex 面板时的结束事件不补记。

项目导航启用时，聊天标题左侧的返回箭头隐藏，新聊天页也不显示，通过左侧列表切换聊天；关闭导航后恢复官方按钮。底部“返回原版界面”图标保持可用。

每个项目行最右侧的 `＋` 在该项目的完整目录中打开独立的当前宿主新聊天草稿；点击不会折叠项目，也不提前创建线程或发送消息。“全部项目”中的其他项目、同名不同路径项目、多根工作区中的各根目录及 worktree 分组均使用被点击的目录，不切换 VS Code 工作区。导航显示当前新聊天的项目名，悬浮可查看完整目录；“当前”标签仍表示当前 VS Code 工作区。

项目新聊天复用官方草稿存储，按完整目录及首页／面板入口隔离，包括结构化草稿和附件。Linux 目录保留大小写、反斜线和尾部空格，Windows 草稿键保持原有大小写兼容规则。普通新聊天操作返回最近使用的草稿入口，项目草稿首次发送后沿用官方清理流程。新建时及首次发送前检查目录；POSIX 宿主同时要求读取与目录搜索权限，Windows 检查可用的目录访问权限；校验后权限变化导致的创建失败仍沿用官方草稿恢复流程；目录不存在、不是文件夹或无法访问时提示错误，保留草稿，不回退到当前窗口目录。“未分类”分组禁用新建。项目按钮创建的是当前宿主上该目录的聊天，后续历史聊天仍沿用其原有运行模式。

未指定聊天时，右侧保留官方首页输入框，隐藏重复的最近聊天列表和“聊天”标题，作为空白待输入页；指定历史聊天的入口仍打开对应对话。进入空白页、输入草稿及切换聊天不会创建聊天，首次发送沿用官方创建流程，收到官方创建成功事件后，列表立即显示真实聊天编号及已有标题，没有标题时显示“未命名聊天”，不等待标题生成或完整分页；当前聊天沿用官方路由同步高亮。标题事件直接更新对应条目。刚创建的聊天在后台列表收录且标题同步前保留于当前面板内，切到其他聊天或草稿、手动刷新和迟到分页不会将它移除；归档会清除该临时记录。后台确认后由普通列表维护，不额外轮询或提前创建线程。

普通“新聊天”按钮及官方新聊天命令返回当前面板的草稿入口，不重置官方编辑状态。空白页的未发送草稿在切到历史聊天再切回后保留，历史聊天有各自的草稿；官方首页与专用新面板入口保持各自原有草稿身份。增强层不复制输入框文字、不接管草稿存储，结构化内容由官方保存；带明确预填内容、项目选择等特殊操作仍走官方流程。发送失败时草稿沿用官方恢复机制，发送成功后沿用官方清理机制。切换行为仅针对已适配版本验证。

顶部图标刷新列表和收起导航；`Alt+/` 在当前聊天面板内收起或展开导航，输入框聚焦时也可使用，不改变草稿；快捷键与图标使用同一套状态并记住选择。导航关闭后快捷键不再生效。拖动分隔线调整宽度，也可聚焦分隔线后使用左右方向键。列表支持上下、Home、End 移动焦点，项目支持左右方向键折叠与展开。窗口宽度不足 640 像素时导航默认收起，显式操作后记住用户选择。

筛选、折叠状态、宽度及启用状态保存在官方插件的独立命名空间 `vscodexLayer.navigationState.v1`。宿主按具体操作串行保存并广播版本化状态：标量偏好按最后一次操作保存，置顶及折叠按项目修改，未读由宿主按轮次维护，已读回执不能清除新轮次。前端保留待提交操作，失败可重试；旧偏好和未读记录兼容读取。不占用官方 Webview 的草稿状态。手动项目目录登记独立保存在 `vscodexLayer.projects.v1`，与置顶及其他导航偏好分开；宿主串行保存目录变更并通知同宿主的其他面板，不跨主机同步。底部返回图标会取消延迟保存、等待已有偏好写入，再保存停用状态并恢复原版布局；等待期间导航暂停操作，失败保留导航及待提交修改，可重试。再用左下角图标启用导航；这不等于卸载文件补丁。列表读取失败时保留已显示内容并显示错误，可刷新重试。

适配层使用已安装插件的现有 App Server 连接读取 `thread/list`。导航通过官方 `navigate-to-route` 消息在发起请求的 Webview 打开聊天。前端路由接入点报告当前路径及查询参数；项目草稿用 `vclProjectCwd` 携带目录，接入官方路由、草稿身份、配置读取和首次创建参数，创建及发送仍由官方完成。普通新聊天操作通过同面板官方路由返回草稿入口，不替换官方路由器。增强脚本保留官方 VS Code API 的一次获取机制和 `getState`、`setState` 行为，不另起 Codex 进程、不主动发送聊天消息。

目录项目草稿没有桌面项目编号，创建时不提交桌面项目归属，避免被登记为需要桌面目录分配的无项目线程。若旧补丁已创建线程但首条消息报错 `projectless-thread-cwd not supported in extension`，更新后用项目 `＋` 新建聊天；补丁不自动改写失败线程的历史或归属。

这属于本地增强补丁，不是官方提供的稳定 UI 扩展接口。相关公共文档：[VS Code Webview](https://code.visualstudio.com/api/extension-guides/webview)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)。

## 验证

`node --test tests/patch-engine.test.mjs` 检查补丁应用、单命令更新、重复执行、部分恢复、冲突及损坏备份保护。

`node --test tests/host.test.mjs` 使用替身连接检查摘要读取、同面板导航、项目目录校验、Linux SSH 宿主支持及不支持的远程模式拒绝。真实 VS Code 验收需要另行启动窗口，仓库脚本不自动进行。

`node --test tests/bootstrap.test.mjs` 检查官方 API 的一次获取和草稿状态透传。`node tools/check-adapter.mjs` 只读本机官方插件，在临时副本检查严格模式接入补丁的语法、应用与恢复。

补丁生成时核对菜单桥新增的具名导入与官方目标模块的导出表；内部函数名不能代替公开导出名，依赖缺失时在安装前拒绝补丁。适配检查同时执行原生聊天菜单组件、Portal 桥和归档恢复桥的无界面验证：目标聊天隔离、原生重命名参数、归档完成回调、运行中确认、原有快捷键注册，以及恢复服务参数、失败、已恢复但加载失败、缓存失效和面板卸载清理。`node tools/check-ui.mjs` 使用模拟原生菜单检查左侧入口、右键、键盘和焦点、非当前聊天操作、失败保留及归档返回草稿；`node tools/check-ui.mjs --archive` 专项检查归档分页、独立搜索和筛选、折叠／滚动／焦点保留、迟到响应隔离、恢复失败与重试、重复点击保护、仅恢复和恢复后查看、部分恢复及空状态。模拟检查不代替真实 VS Code 的分享、剪贴板、恢复及账号能力验收。

`node tools/check-compatible.mjs` 对当前实际启用版本生成结构兼容补丁，检查动态资源选择、全部增强标记和 JavaScript 语法，在隔离环境执行宿主入口以验证初始化、SSH / WSL 支持边界和错误日志；同时执行官方 Composer 与创建参数转换，使用真实归属保存回调和首次消息工作区判断，复现旧补丁的无项目目录分配错误，并检查修复后的跨目录首次消息准备及失效目录拒绝。配置读取、线程创建和消息发送以替身截停，不产生实际聊天；最后在临时副本验证补丁应用、已安装补丁的更新、重复应用和恢复，不修改实际插件。

两个适配检查均从目标包提取实际活动分类和摘要渲染入口，在 VM 中检查非空／空摘要、标题保留、当前和历史正文透传、其他活动保持原行为、增强开关及桥接缺失时的隐藏；以 React 状态、JSX 和布局替身执行真实官方组件，检查生成中及完成后默认折叠、展开回调、实时正文、自然高度、完成后保留展开状态及手动收起后不自动打开。`tests/compatibility.test.mjs` 检查摘要结构缺失、重复候选、重复补丁和控件变化时拒绝转换；宿主与桥接检查覆盖独立阅读的内存文档、正文更新顺序与宿主／聊天／摘要隔离。`node tools/check-ui.mjs --reasoning` 使用已有浏览器无头检查窄侧栏、长路径、无空格文本及代码折行。以上不能代替真实 VS Code 中点击展开、Markdown 主编辑区预览和实时显示的人工验收。

接入检查也支持 `--extension "插件绝对路径"`，目标已经应用补丁时从经过校验的备份读取原件，不复制已修改文件作为原件。

`node --test tests/navigation.test.mjs` 检查路径分组、手动登记合并与保留、创建时间及项目固定排序、当前项目筛选、搜索、完整分页，以及提醒优先级、实时结束提示和查看清除。宿主测试同时检查手动项目独立存储、多面板并发保存、目录选择与取消、保存失败恢复、失效目录移除、状态标记转发、结束事件字段过滤和未读状态保存。相关检查按改动范围运行，不自动启动桌面窗口。

`node tools/check-ui.mjs` 使用本机已有 Chrome、Edge 或 Linux Chromium 的无头模式，通过模拟官方消息桥接验证导航交互、跨页读取、固定顺序与滚动焦点、文件夹添加与移除、重复登记、错误恢复、空项目重开保留、官方根节点与草稿保留、返回原版以及宽窄布局。`node tools/check-ui.mjs --reading` 仅检查阅读回执，使用浏览器实际输入事件验证当前与长回复可见性、反向滚动、旧消息、自动滚动、导航区、隐藏和焦点、完成前后时序、新轮次保护及审批／输入／错误提示保留。不安装浏览器、不弹出窗口，使用临时独立浏览器配置并在退出时清理。模拟界面截图写入被 Git 忽略的 `.scratch/ui`，不能代替真实官方聊天验收。

严格模式的 `check-adapter.mjs` 还在隔离环境执行已核查 Windows 包的官方路由、草稿、目录选择及首次提交函数，检查同名项目、首页／面板草稿隔离、结构化草稿、配置与创建参数和失效目录拒绝回退；首次提交截停在创建请求前，不产生真实聊天。无头界面检查模拟输入框卸载和重建，覆盖项目按钮、草稿切换、失败保留、发送后清理及新聊天高亮。它们不等于真实 VS Code 中的完整聊天验收；流式回复、停止、审批和代码变更查看仍需人工验收。
